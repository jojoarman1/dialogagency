## Project state

Agency landing site (brand: **dialog**). The home page (`src/app/[lang]/(main)/page.tsx`) is a full-screen hero with the word "dialog" drawn by a WebGL prism shader; there is no database.

- **Languages (ru/en)**: every page lives under `src/app/[lang]/` (`/ru`, `/en`; the root layout is `[lang]/layout.tsx` with `generateStaticParams`). `src/proxy.ts` (Next 16's middleware) sends locale-less paths to `/<lang>` by the `dialog-locale` cookie, else `Accept-Language` (307), the old `/privacy` and `/consent` to `/ru/...` (308), and sets the cookie on any locale page. Unknown paths hit `[lang]/[...rest]/page.tsx`, which calls `notFound()` (no experimental `global-not-found`). Texts are in `src/config/dictionaries/` (`ru.constants.ts`, `en.constants.ts`, typed by `Dictionary` and keyed by the config ids such as `ChatStepId`, `FaqId`, `ProjectSlug`, so a missing translation fails to compile; `{name}` placeholders go through `fillTemplate`). Server components read them with `getRequestDictionary()` / `getRequestLocale()` (`src/lib/dictionary.service.ts`, `lang` from `next/root-params`), client ones with `useDictionary()` under `DictionaryProvider` (a plain React context: reactuse `createContext` keeps its first value in state, so it would stay on the old language). Internal links go through `localizePath(locale, path)`. Chat answers carry option ids, not wording: the server validates ids and the Telegram message is always in Russian (`RU_DICTIONARY`). `LocaleSwitch` is a segmented control (`difference` in the blended header, `onDark` in the menu); changing the language remounts the whole page, so its thumb finishes travelling before it navigates.
- **Prism title**: `src/components/elements/home/` — `HeroIntro` (`useHeroIntro`) lazy-loads `PrismTitleScene` (a plain `<canvas>` with raw WebGL, no three.js: `src/lib/prismGl.ts` sets up one full-canvas quad, `usePrismRenderer` draws it, `ssr: false`), completes its loading task on the first frame; the word then fades in plain dark (`opacity`) and the effect grows in after it (`aberration` from 0); GSAP tweens the plain numbers in `src/lib/prismState.ts`, which become the shader uniforms. The canvas texture is sized to the WebGL buffer exactly, otherwise fractional pixel ratios blur the edges. `usePrismTitle` draws the word with the page's Geist into a canvas texture (plus a blurred copy), and `src/lib/prismShader.ts` reproduces Figma's "Lens distortion" (lateral, aberration 0.83, centre 50%/60% of the text box): crisp glyph outlines, a colour-split smear inside the letters that grows with the distance from the centre, which drifts slightly towards the pointer. The real `h1` is `sr-only`; `PrismTitleFallback` + `.prism-title` in `globals.css` is a CSS approximation for browsers without WebGL.
- **Loading**: there is no preloader screen. Content that must be ready before the intro registers a task with `useLoadingTask()` and calls `complete()`; `useIsLoadingFinished()` from `src/stores/loading.ts` turns true once the last task completes and stays true (the title fades in, then the hero caption and chat button appear).
- **Header**: the fixed, transparent `Header` (`src/components/layout/`, rendered by the `src/app/[lang]/(main)/layout.tsx` route group, so the `not-found` page has none). From 1024px wide the section links, Telegram and the language switch sit inline (`HeaderNav`); below it (the mobile layout) the header gets the "Меню" button that morphs into `MenuPanel`, a mobile-only panel with the links and the language switch.
- **Chat** (`src/components/layout/Chat.tsx`, in the `(main)` layout): `useChat` runs the panel: the dark "Начать проект" button expands into it by tweening the inner layer's `clip-path` inset and radius (from the button's radius to the panel's, which is set on the outer `section` that also carries the drop shadow), and the button's arrow tile travels with the corner and crossfades into the minus close tile; the button is visible from the first paint. The open/close timelines are in `src/lib/chat.panel.ts`; the desktop sound toggle next to the button (`sideControl`) rides along to the open panel's right edge. Conversation markup is in `src/components/layout/chat/`, `useChatForm` runs the conversation on top of `useChatSteps` (answers, current step, editing) and `useChatInput` (the contentEditable answer), with the step reveal and the thanks in `src/lib/chat.reveal.ts`. Steps and branches live in `src/config/chat.ts`; each new step's line is typed like a person would (`addTyping` in `src/lib/chat.typing.ts`: characters pop in at an uneven pace, pausing between words and after punctuation) through per-character spans the hook creates inside a span React renders empty (so layout is reserved and words never jump lines), answers can be clicked to edit (later answers are dropped). "Отправить" posts the answers to `src/app/api/lead/route.ts`, which re-validates them (`lead.schema.ts`: known steps, real options, per-step length, an email or Telegram contact), rate-limits per IP and sends them to the Telegram channel via the bot (`TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHAT_ID`, validated in `src/env.ts`; on the server in `/home/vice/frontend/dialog/.env`, locally in `.env.local`). The chat opens by itself once the page is scrolled to the end, unless the visitor already opened it or is on the mobile layout (`useChatAutoOpen`). The button and the open panel ride up with the footer instead of covering it (`useChatFooterOffset`, `--chat-footer-offset`). Metrika goals trace the funnel: `chat_open` / `chat_auto_open`, `chat_answer_<stepId>` (picked options as params, never typed text), `chat_send`, `chat_sent`, `chat_send_error`. "Отправить" (`ChatSendButton`) is a light `TileButton`; while the lead is sending, the email beside it folds away, the button spreads over the whole row reading "Отправляем заявку…", and a failed send turns it red (`danger` tile) with "Не получилось, отправить ещё раз" (screen readers also get an alert with the email); the consent box is the shared `Checkbox` (`src/components/ui/`, registered in `biome.json` as an input component for the label rule).
- **The prism title renders on demand**: nothing draws unless something calls `requestRender()` from `usePrismRenderer` (coalesced to one draw per animation frame), so anything that changes `PrismState` must call it. The pointer follow draws synchronously in its own animation frame (a requested render would land a frame late and judder) and stops once the centre settles. Don't call `loseContext()` on unmount: the canvas hands the dead context back on the next `getContext()`, which breaks Strict Mode's second effect run.
- **Zoom is disabled** like on snp: viewport `userScalable: false`, `touch-action: pan-x pan-y` on `html`.
- **Projects** (`Projects` → `ProjectCard` → `ProjectCover`, data in `src/config/projects.ts`, media in `public/projects/<slug>/`): the cover is a `next/image` served as a ready WebP file (`images.unoptimized` in `next.config.ts`: no image optimizer runs on the server); `useReelPlayback` (in `ProjectArticle`) sets `data-active` on the whole project, photo and text, on mouse hover, or while it crosses the middle of the screen on touch screens: the reel video (`preload="none"`, poster first) rises, grows and plays, and the photo dims (`.project-reel*` in `globals.css`). The photo also scrolls inside its cover (`useCoverScroll`, ScrollTrigger scrub): it is `COVER_SCROLL_OVERSCAN` taller than the cover and travels that extra while the cover crosses the screen.
- **Page grid**: every section and the header keep 28px side gutters (`px-7`, mobile `px-4`). Projects, the testimonial and the FAQ share `SECTION_GRID_CLASS_NAME` (`section.styles.ts`): a centred middle column exactly a project row wide (980 cover + 16 + 430 text = 1426), the section label in the left side column; no hand-tuned left margins.
- **Testimonial** (`src/config/testimonial.ts`): scroll-linked with no pinning (`useTestimonialReveal`, ScrollTrigger + SplitText): the card widens while the quote types itself out letter by letter, then the author fades in; done by the time the card is mid-screen (`clamp()` keeps that reachable at the end of the page).
- **Services** (`src/config/services.ts`): a full-screen section; clicking a service (`ServiceOption`) makes it white and shows its picture on the left: a lens collage (`LensCollage`, WebGL), paper and cut-outs (`sprites`, `LensSprite` in `src/config/lens.types.ts`) from `public/services/<id>/`, coming in when scrolled to and drifting with the pointer. The cut-outs share one atlas texture (`lens.atlas.ts`, up to `LENS_MAX_SPRITES`); each has its box in fractions of the paper, its side to come in from, its delay and its parallax depth (`lens.sprites.ts` places them), and its own progress in the view, so an interrupted entrance or exit turns around without a jump. "Стратегия бренда" is one cut-out over its paper; "Стратегия развития" is a plain white table the size of the paper with the four meeting pictures around it (`meeting.sprites.ts`; the left one drifts least, there is little room before the screen's edge). "Дизайн сайта" builds a site's wireframe on a white page block by block, top to bottom (`website.sprites.ts`; the block images are drawn at 2x with rounded corners, dark #3b3b39, light #f4f4f1 and the site's accent for buttons). With a mouse its blocks are playable (`label` on a sprite): `LensControls` lays an invisible box over each one, moved onto its cut-out after every frame (`render()` returns where each ended up), that shows a Figma-like selection frame (`--frame` blue) and catches the pointer for `useLensInteraction`: a hovered block lifts and is drawn over the rest, a dragged one follows the pointer and springs back when let go (`parent` cut-outs ride along), `isPressable` buttons squeeze and click. Twelve cut-outs is the shader's limit. "Разработка сайта" is one developer picture three times on a pink sheet (`developer.sprites.ts`): the nearest rises in, the other two come out of it (`emergeFrom`: they start in its box, bulging hard, and straighten on the way). "Айдентика" is a sheet of logos that smears after the mouse (`hasFlow`): `lens.flow.ts` runs a 128px flowmap (after supersolid.agency, the old project-cover effect) only while the pointer moves and for 150 frames after (counted in frames so it always fades to zero), and the lens shader pushes the paper along it, inside the paper only. The other services use the shared lined sheet `public/services/paper.webp` through the same lens (no cut-out, stretched over the column). The paper flattens out completely once it has come in. Switching (`useServiceSwitch`) highlights the new title at once, but the shown collage first leaves (`LENS_EXIT`: the cut-outs go back to their sides in reverse order and fade, the paper shrinks back into its middle), then the new one comes in; `useLensEntrance` tweens from wherever the view is and must not revert on update (that snaps the paper to 0). On mobile the picture is a small 104-wide column right of the list that floats (`animate-levitate`) instead of following the pointer.
- **Footer** (`Footer` in the `(main)` layout): big section links from `FOOTER_LINKS` (`FooterNav`, the client part; "Старт" opens the chat), the email and the privacy link, Telegram.
- **Sounds** (SND01 "sine" by snd.dev, free for commercial use; mp3s in `public/sounds/`, list and volumes in `src/config/sound.constants.ts`): off by default, switched by `SoundToggle` (next to the chat button on desktop, next to «Меню» on mobile; the choice lives in sessionStorage, `src/stores/sound.store.ts`, so every new visit starts muted). `src/lib/sound.player.ts` plays them through Web Audio (no `<audio>`: no iOS delay, fast repeats overlap); the files are fetched while the page is idle (`prefetchSounds`), but the context can only start from a user gesture, so decoding and `unlockSounds()` run on the toggle click and on any `pointerdown` once enabled. `useSoundEffects` (in `Header`) puts one listener on the document: `tap` on hovering and clicking links/buttons, `type` on text input. Controls with their own sound carry `data-own-sound` (the toggle, the chat open/close buttons). The chat plays `transitionUp`/`transitionDown`, `type` per typed character and `notification` when the lead is sent.
- **Film grain**: `GrainOverlay` (root layout) is a fixed layer above everything, tiled with `public/grain.png` and jumped between six offsets twice a second (`.grain-overlay` in `globals.css`), the technique supersolid.agency / bymonolog.com use. The tile is generated: every pixel one of 7 greys at ~7% alpha, about half near-black, so it reads on light and dark. Nothing else adds its own grain.
- **Analytics**: Yandex Metrika (`YandexMetrika`, id and options in `src/config/analytics.ts`), loaded `afterInteractive` and only on the production hostname. Its cookies count as personal data under 152-FZ, so `CookieConsent` (root layout) mounts it only after the visitor presses "Принять" in `CookieBanner`; the choice lives in localStorage (`src/stores/cookieConsent.ts`).
- **Personal data (152-FZ)**: the chat sends a lead only with the separate consent checkbox ticked (`ChatConsent`; the server also requires `consent: true`). `/<lang>/privacy` and `/<lang>/consent` render `LegalDocument` from the legal dictionaries (`ru.legal.constants.ts` is binding, `en.legal.constants.ts` is a translation that says so); the operator's details are in `src/config/legal.ts` (self-employed; the email is the address for requests). The privacy link is also at the bottom of the CTA.
- **Animations use GSAP** (`gsap` + `useGSAP` from `@gsap/react`, registered in the hook module). DOM animations tween CSS variables or styles directly instead of React state (e.g. the chat panel's `clip-path` inset).
- **SEO**: name, email, theme color and URL live in `src/config/site.ts`, title and description per language in the dictionaries; they feed `[lang]/layout.tsx` metadata (canonical + hreflang from `getAlternates`, `x-default` is ru), JSON-LD in `page.tsx` (`getHomeJsonLd`), `sitemap.ts` (every page × language), `robots.ts`, `manifest.ts`. The OG image is `public/og.png` (a static 1200×630 file from the design), set in metadata because the `opengraph-image` file convention can't take a translated alt. Icons are RealFaviconGenerator files: `favicon.ico`, `icon0.svg`, `icon1.png`, `apple-icon.png` in `src/app/`, manifest PNGs in `public/`. The production domain is `https://bydialog.ru` (self-hosted on the owner's server, not Vercel); `NEXT_PUBLIC_SITE_URL` overrides it at build time.

## Commands

Package manager is **Bun** (`packageManager: bun@1.3.11`, `bun.lock`). Use `bun`, not npm/yarn/pnpm.

- `bun install` — install dependencies
- `bun dev` — dev server at http://localhost:3000 (also regenerates `AGENTS.md`)
- `bun run build` / `bun start` — production build / serve
- `bun run lint` — `biome check` (lint + formatting + import sorting); `bunx biome check --write` to auto-fix
- `bun run format` — `biome format --write`
- `bunx tsc --noEmit` — typecheck (no script defined)
- `bun test` — runs the `*.test.ts` files next to the code they test (`node:test` + `node:assert`; no React component tests yet).

## Deploy

`.github/workflows/ci.yml`: every push and PR runs lint + build (`next build` also type-checks). A push to `main` then ships the `output: 'standalone'` build (with `public/`, `.next/static` and `ecosystem.config.cjs` copied in) over SSH to the owner's server, which also hosts viceseason (pm2 `vcssn-front` on 3000, its API on 3002): it lands in `/home/vice/frontend/dialog/app`, runs as pm2 `dialog` on `127.0.0.1:3010` behind nginx, and rolls back to the previous build if it doesn't answer. Secrets: `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_SSH_KEY`. nginx (`/etc/nginx/sites-available/bydialog.ru.conf`, next to the viceseason configs) serves `/_next/static` and `public/` files straight from that `app` folder and proxies the rest to the `dialog_front` upstream, so moving the build folder breaks static files.

## Stack and conventions

- **Next.js 16 (App Router) + React 19.** Per `AGENTS.md`, check `node_modules/next/dist/docs/` (`01-app/`, `03-architecture/`, …) before using Next APIs — don't rely on memory of older versions.
- **React Compiler is enabled** (`reactCompiler: true` in `next.config.ts`). Don't add manual `useMemo`/`useCallback`/`React.memo` for performance; the compiler handles memoization. Don't call store hooks as `store.use()` (e.g. reactuse `createStore`): the compiler treats a method named `use` like React's conditional `use()` and may skip it, breaking the hook order — wrap it in a named hook (`useIsOverLogo` in `src/stores/cursor.ts`).
- **Typed route helpers**: layouts/pages use Next's global generated types (e.g. `LayoutProps<"/">` in `src/app/layout.tsx`, generated into `.next/types`) rather than hand-written prop types.
- **Biome, not ESLint/Prettier.** Config in `biome.json`: single quotes, no semicolons, no trailing commas, 2-space indent, line width 100; recommended rules plus the `next` and `react` domains. Import groups: packages → `@/` aliases → relative paths → styles (side-effect CSS imports are not moved automatically, keep them last by hand).
- **Barrel packages** (`@siberiacancode/reactuse`) are listed in `experimental.optimizePackageImports` in `next.config.ts`; add new barrel-style packages there.
- **Tailwind CSS v4** via `@tailwindcss/postcss`. There is no `tailwind.config.*`; theme tokens live in `src/app/globals.css` under `@theme`. The site is light (`color-scheme: light`, background `#e8e8e3`, text `#080807`, tokens `--background`/`--foreground`); `font-sans` is Geist, `font-mono` is IBM Plex Mono, loaded in weight 400 only (add weights in `layout.tsx` if a new place needs them).
- **1rem = 1px of the design artboard.** `html` font-size is `min(100vw / W, 100svh / H)` (svh, so iOS Safari's toolbar doesn't rescale the page while scrolling) for two artboards, as in the design: 1920×1080 (desktop, from 1024px) and 480×667 (mobile, below 1024px, scaled up to fill tablets). The edge is Tailwind's `lg`: mobile overrides are `max-lg:`, desktop-only ones `lg:`; there is no tablet layout, so the whole layout scales like the Figma frame. Tailwind's rem scales (spacing, text, radius, container) are redefined in artboard px, so `p-4` = 16px and `text-sm` = 14px at artboard size; xs–base text has a 12px floor. Write Figma pixel values for layout as `rem` (`w-[320rem]`); use `px` only for things that must not scale (hairlines, minimum sizes). **Text is different, like bymonolog.com**: the layout keeps growing with the screen, but text stops at the artboard size, so font sizes, text line heights and tracking use `--text-unit` (`min(1rem, 1px)`): `text-[calc(42*var(--text-unit))]`, `leading-[calc(53*var(--text-unit))]`, `tracking-[calc(-1.6*var(--text-unit))]`; the `text-xs`…`text-9xl` tokens already do. Relative values (`leading-[1.1]`, `tracking-[-0.03em]`) need nothing. The prism word caps the same way in `usePrismRenderer`. Interface chrome holds its size the same way, all of it in `--text-unit`: the header, tile buttons (`tile.styles.ts`), the chat button and panel, the mobile menu, the cookie banner and the hero h1 next to the header. Media queries are unaffected (they use the browser default 16px).
- **Text selection** inverts the page colours (global `::selection`).
- **CSS transitions** default to the `--ease-smooth` token (`cubic-bezier(0.22, 1, 0.36, 1)`, 500ms); GSAP timings live in `src/config/animation.ts`.
- **Structure**: source lives under `src/`, import alias `@/*` → `./src/*`. Custom hooks go in `src/hooks/` (named `use<Feature>`, params type `Use<Feature>Params`, grouped return like `{ state, refs }`); page sections in `src/components/elements/<page>/`; global layout pieces in `src/components/layout/`; icons as SVG React components in `src/components/icon/`; shared stores in `src/stores/`; non-React helpers in `src/lib/`; constants in `src/config/`; conditional classes via `clsx`.
